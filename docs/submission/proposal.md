## 1. 앱 한 줄 소개

전기차 가족 여행에서 식사와 화장실, 아이 휴식, 충전을 한 번에 비교하고, 고른 정차 지점을 지금 경로의 경유지로 바로 추가해 주는 정차 도우미다.

## 2. 기획 배경

전기차로 가족 여행을 하면 충전 조건과 가족의 정차 필요를 따로 찾아 비교해야 한다. 가족의 정차 필요는 식사, 화장실, 아이 휴식이다. 운전 중에는 이 비교를 할 수 없고, 정차한 뒤에 정하려 하면 원래 경로상의 해당 지점은 이미 지나친 뒤다.

- 이 불편이 얼마나 자주, 얼마나 크게 생기는지는 아직 검증하지 않은 가설이다.
- 기존 내비와 제조사 앱, 지도 앱을 함께 쓰는 방식과 같은 조건에서 비교해 본 적이 아직 없어서, 이 앱이 더 낫다고 말할 근거는 없다.

## 3. 앱 주요 기능 및 차량 특화 요소

| 기능 | 내용 | 차량 특화 |
|---|---|---|
| 이동 상황 판별 | AAOS `CarUxRestrictions`(주의분산 제한 여부)로 정차와 주행을 구분한다. 상태를 알 수 없으면 주행 중과 같은 제한을 적용한다 (ADR-0004). | 주행과 정차 맥락을 구분한다. |
| 주행 중 제한 | 상세 입력, 비교, 스크롤을 막는다. 큰 카드는 최대 2개만 보여 주고, 한 번 탭으로 선택하며, 10초 동안 취소할 수 있다 (ADR-0003). | 운전자의 주의분산을 최소화한다(`distractionOptimized`). |
| 여행 조건과 정차 필요 입력 | 목적지와 도착 희망 시간을 정하고, 식사, 화장실, 아이 휴식 중 필요한 것을 여러 개 고른다. 계정 없이 시작하고, 상세 입력은 정차 상태에서만 받으며, 주행이 시작되면 초안을 보존한다. | 정차 중에만 입력을 받는다. |
| 차량 에너지 확인 | Vehicle SDK로 EV 배터리 잔량, 충전 상태, 주행 가능 거리를 읽는다. 값이 들어오지 않으면 수동 입력을 받고 자동값과 구분해 표시한다. | 차량 데이터를 함께 쓴다. |
| 정차 후보 추천과 비교 | 후보는 최대 3개다. 가족 필요 충족 여부, 추천 이유, 도착 시간 변화, 이동 부담 순으로 보여 준다. 데이터 출처가 실제인지 가상인지와 확인 상태를 문구와 아이콘으로 함께 표시한다. | 충전 정보와 경로 맥락을 함께 쓴다. |
| 길 안내 전달 | 선택한 지점을 `NaviHelper.addWaypoint`로 경유지에 추가하고 원래 목적지는 유지한다(에뮬레이터 실측). 경유지가 이미 2개 차 있으면 교체할 대상을 묻는다. | 내비와 연동한다. |
| 충전 중 가족 활동 안내 | 정차해서 할 일 체크리스트와, 차량에서 받은 충전 상태 및 배터리 잔량을 보여 준다. 충전이 끝나면 자동으로 출발을 안내한다. 남은 시간은 차량이 주지 않으므로 추정하지 않는다. | 전기차 충전 시간을 활용한다. |
| 예외 대응 | 권한 거부나 데이터 미수신 때는 실패한 항목과 제한을 안내하고 수동 입력으로 대신한다. 마지막으로 확인한 값은 출처와 시각을 함께 보여 준다. | 차량 환경의 불확실성에 대응한다. |
| 음성 안내 | 결과를 1~2문장으로 읽어 준다. 주행 중에는 후보를 최대 2개까지 번호로 안내한다 (ADR-0002). | 핸즈프리로 쓴다. |

범위 밖은 주유 전후 안내, 예약과 결제, 자체 지도와 길 안내, 수익화, 음성 입력(STT)이다. 지표 수집도 시연 범위 밖이며 PT 이후에 다룬다.

## 4. 주요 사용 시나리오

운전자와 동승자가 전기차로 서울에서 장거리 여행 중이다. 배터리 잔량이 줄고 있고 아이가 배고프다고 한다.

1. 휴게소에 정차하면 앱이 정차 상태를 인식해 상세 화면을 연다. 목적지와 필요한 것(식사, 아이 휴식)을 입력한다.
2. 앱은 배터리 잔량과 입력을 바탕으로 정차 후보 최대 3개를 가족 필요 충족 여부 순으로 비교한다.
3. 후보를 고르면 앱이 현재 경로에 경유지로 추가하고, 원래 목적지는 그대로 둔다.
4. 이미 출발해 주행 중이면 앱이 상세 비교를 막고 큰 카드 2개만 보여 준다. 한 번 탭하면 선택한 지점이 바로 경유지에 반영되고, 10초 안에 취소할 수 있다. 결과는 음성으로 짧게 알려 준다.
5. 충전소에서 충전을 시작하면 앱이 정차 중에 할 일(식사, 화장실, 아이 휴식) 체크리스트와, 차량에서 받은 충전 상태 및 배터리 잔량을 보여 준다. 충전이 끝나면 출발을 안내한다.
6. 권한이 거부되거나 데이터가 들어오지 않으면 무엇이 안 되는지 알려 주고, 정차한 뒤 수동 입력으로 이어 간다.

## 5. 개발 계획

**구현 방식**: Pleos Connect(AAOS) 단일 앱이며 Kotlin과 Jetpack Compose로 만든다. 멀티 모듈 Gradle과 Google 앱 아키텍처를 쓰고, Pleos SDK 의존은 `:impl:pleos` 한 곳에 둔다 (ADR-0001, ADR-0006). 기능 로직은 `:feature:*`에 두고, SDK와 플랫폼 접근은 Ports 인터페이스 뒤에 둔다. 그래서 SDK가 열리면 구현만 교체하면 된다.

**SDK와 API 사용 계획** (Pleos My Project 콘솔 확인, 2026-11-07):

| SDK | 콘솔 상태 | 용도 | 계획 |
|---|---|---|---|
| Vehicle State | 사용 가능 | EV 배터리 잔량, 충전 상태, 주행 가능 거리 | 구현하고 앱에 연결을 마쳤다(`PleosVehicleEnergySource`). 주행 가능 거리를 읽으려면 `CAR_DRIVE` 권한이 필요하다. 주행과 정차 판별은 기어 대신 AAOS `CarUxRestrictions`로 구현했다. |
| NaviHelper | 사용 가능 | 정차 지점 경유지 추가와 취소, 경로 상태 조회 | 구현하고 앱에 연결을 마쳤으며(`PleosNaviGateway`), 에뮬레이터에서 실측했다. |
| FusedLocation | 준비 중 | 현재 위치 | 준비 중이어서 Android `LocationManager`로 대체하고, 오픈 후 전환한다. |
| TextToSpeech | 준비 중 | 결과 음성 안내 | Android `TextToSpeech`로 대체하고, 오픈 후 Pleos `ON_DEVICE`로 전환한다. |
| SpeechToText | 준비 중 | 음성 요청 | 시연에서 제외하고, 오픈 후 검토한다. |

- 음성은 차량 밖으로 보내지 않도록 `ON_DEVICE`로 고정한다.
- Pleos SDK에는 시설 검색 API가 없어서, 식당, 화장실, 충전소 후보는 지금 앱에 넣어 둔 시연 구간 시설 데이터로 만든다. 이 데이터는 실제와 가상이 섞여 있고 화면에 출처를 표시한다. 외부 시설 데이터(API)는 공모전 규정을 운영사에 확인한 뒤 붙인다 (ADR-0001).
- 상시 무료로 운영하며 현금 지출은 0원이다 (ADR-0005). 무료 한도를 넘을 수 있는 외부 API는 가상 데이터로 대체한다.

**개발 일정**:

| 시점 | 내용 |
|---|---|
| ~11-15 (1차 접수) | 최소 동작 앱, 시연 영상, GitHub(소스와 APK)를 낸다. |
| ~12-03 (2차 PT 전) | 핵심 SDK 연계와 예외 대응을 에뮬레이터에서 실제 동작으로 검증한다. |
| 선정 후 | 준비 중인 SDK가 열리면 전환하고, 앱 마켓에 입점하면 가상 데이터를 실제 데이터로 바꾼다. |

**검증 방식**: 단위 테스트와 에뮬레이터 E2E로 검증한다. E2E에서는 `adb`와 Virtual Console로 기어, 배터리, 충전, 속도를 조작한다.

## 6. 기대효과 및 발전 가능성

- **사용자 가치**: 충전 조건과 가족 필요를 한 번에 비교해 정차 계획에 드는 시간을 줄이고, 주행 중에도 안전하게 경유지를 반영하게 한다.
- **타깃**: 전기차로 가족 여행을 하는 운전자와 성인 동승자다. 내연기관 차량은 후속 범위로 둔다.
- **예상 MAU와 Retention**: 근거로 삼을 수치가 아직 없어 목표값은 정하지 않았다. MAU는 Pleos 탑재 전기차 중 가족 동반 장거리 이동 차량 수에 설치율과 월간 사용률을 곱해 산정한다. 탑재 대수와 설치율은 App Market 입점 후 실제 값으로 채운다. 가족 여행은 주말과 연휴에 몰리므로 월간보다 분기 재사용률을 Retention 지표로 본다. 분기 재사용률은 같은 차량이 다음 장거리 여행에서 다시 쓰는 비율이다. 시연 단계에서는 정차 계획 시간, 선택 이유, 해결되지 않은 필요를 관찰해 측정한다.
- **확대 계획**: 내연기관 주유 전후 안내를 추가하고, STT가 열리면 음성 요청을 붙인다. 동의를 받아 정차 가치와 재사용 지표를 수집하고, 실제 시설 데이터로 바꾼 뒤 앱 마켓에 입점한다.
- **한계**: 소규모 표본으로는 일반화할 수 없다. 앱에서 후보를 고른 것이 실제 방문을 뜻하지는 않는다.
