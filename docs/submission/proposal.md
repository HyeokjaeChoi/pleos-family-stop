## 1. 앱 한 줄 소개

전기차 가족 여행에서 식사·화장실·아이 휴식과 충전을 한 번에 비교해, 고른 정차 지점을 지금 경로의 경유지로 바로 추가해 주는 정차 도우미.

## 2. 기획 배경

전기차로 가족 여행을 하면 충전 조건과 가족의 정차 필요(식사, 화장실, 아이 휴식)를 따로 찾아 비교해야 한다. 운전 중에는 이 비교를 할 수 없고, 정차 후에 정하면 이미 원래 경로로 지나간 뒤다.

- 이 불편의 빈도와 크기는 아직 검증하지 않은 가설이다.
- 기존 내비·제조사 앱·지도 조합과 같은 조건으로 비교하기 전에는 우위를 단정하지 않는다.

## 3. 앱 주요 기능 및 차량 특화 요소

| 기능 | 내용 | 차량 특화 |
|---|---|---|
| 이동 상황 판별 | AAOS `CarUxRestrictions`(주의분산 제한 여부)로 정차/주행 판별. 상태를 알 수 없으면 주행 중과 같은 제한 (ADR-0004) | 주행·정차 맥락 |
| 주행 중 제한 | 상세 입력·비교·스크롤 차단. 큰 카드 최대 2개만 노출, 한 번 탭으로 선택, 10초간 취소 가능 (ADR-0003) | 운전자 주의분산 최소화, `distractionOptimized` |
| 여행 조건·정차 필요 입력 | 목적지·도착 희망 시간·식사/화장실/아이 휴식(복수 선택). 계정 없이 시작, 정차 상태에서만 상세 입력, 주행 시작 시 초안 보존 | 정차 시에만 입력 |
| 차량 에너지 확인 | Vehicle SDK의 EV 배터리 잔량·충전 상태·주행 가능 거리. 미수신이면 수동 입력(자동값과 구분 표시) | 차량 데이터 결합 |
| 정차 후보 추천·비교 | 후보 최대 3개. 가족 필요 충족 여부 → 추천 이유 → 도착 시간 변화 → 이동 부담 순. 데이터 출처(실제/가상)·확인 상태를 문구+아이콘으로 표시 | 충전 + 경로 맥락 결합 |
| 길 안내 전달 | 선택 지점을 `NaviHelper.addWaypoint`로 경유지 추가. 원 목적지 유지 (에뮬레이터 실측). 경유지 2개가 차 있으면 교체 대상을 묻는다 | 내비 연동 |
| 충전 중 가족 활동 안내 | 정차에서 할 일 체크리스트 + 차량에서 받은 충전 상태·배터리 잔량. 충전이 끝나면 자동으로 출발 안내(남은 시간은 차량이 주지 않아 추정하지 않음) | 전기차 충전 시간 활용 |
| 예외 대응 | 권한 거부·데이터 미수신 시 실패 항목과 제한을 안내하고 수동 입력으로 대체. 마지막 확인값은 출처·시각을 병기 | 차량 환경 불확실성 |
| 음성 안내 | 결과를 1~2문장으로 읽어 줌. 주행 중 후보는 최대 2개를 번호로 안내 (ADR-0002) | 핸즈프리 |

범위 밖: 주유 전후 안내, 예약·결제, 자체 지도·길 안내, 수익화, 음성 입력(STT), 지표 수집(시연 범위 밖, PT 이후).

## 4. 주요 사용 시나리오

운전자와 동승자가 전기차로 서울에서 장거리 여행 중이다. 배터리 잔량이 줄고 있고 아이가 배고프다고 한다.

1. 휴게소에 정차하면 앱이 정차 상태를 인식해 상세 화면을 연다. 목적지와 필요(식사, 아이 휴식)를 입력한다.
2. 배터리 잔량과 입력을 바탕으로 정차 후보 최대 3개가 가족 필요 충족 여부 순으로 비교된다.
3. 후보를 고르면 현재 경로에 경유지로 추가되고, 원래 목적지는 유지된다.
4. 이미 출발해 주행 중이면 상세 비교는 막히고 큰 카드 2개만 보인다. 한 번 탭하면 즉시 경유지에 반영되고, 10초 안에 취소할 수 있다. 결과는 음성으로 짧게 안내된다.
5. 충전소에서 충전을 시작하면 정차에서 할 일(식사·화장실·아이 휴식) 체크리스트와 차량에서 받은 충전 상태·배터리 잔량을 보여 주고, 충전이 끝나면 출발을 안내한다.
6. 권한 거부나 데이터 미수신 시에는 무엇이 안 되는지 알려 주고 정차 후 수동 입력으로 이어 간다.

## 5. 개발 계획

**구현 방식**: Pleos Connect(AAOS) 단일 앱, Kotlin + Jetpack Compose. 멀티 모듈 Gradle과 Google 앱 아키텍처를 쓰며 Pleos SDK 의존은 `:impl:pleos` 한 곳에 둔다 (ADR-0001, ADR-0006). 기능 로직은 `:feature:*`, SDK·플랫폼 접근은 Ports 인터페이스 뒤에 두어 SDK가 열리면 구현만 교체한다.

**SDK/API 사용계획** (Pleos My Project 콘솔 확인, 2026-11-07):

| SDK | 콘솔 상태 | 용도 | 계획 |
|---|---|---|---|
| Vehicle State | 사용 가능 | EV 배터리 잔량, 충전 상태, 주행 가능 거리 | 구현·앱 연결 완료(`PleosVehicleEnergySource`). 주행 가능 거리는 `CAR_DRIVE` 권한 필요. 주행/정차 판별은 기어 대신 AAOS `CarUxRestrictions`로 구현 |
| NaviHelper | 사용 가능 | 정차 지점 경유지 추가·취소, 경로 상태 조회 | 구현·앱 연결 완료(`PleosNaviGateway`), 에뮬레이터 실측 완료 |
| FusedLocation | 준비 중 | 현재 위치 | 준비 중이라 Android `LocationManager`로 대체, 오픈 후 전환 |
| TextToSpeech | 준비 중 | 결과 음성 안내 | Android `TextToSpeech`로 대체, 오픈 후 Pleos `ON_DEVICE`로 전환 |
| SpeechToText | 준비 중 | 음성 요청 | 시연에서 제외, 오픈 후 검토 |

- 음성은 차량 밖으로 보내지 않도록 `ON_DEVICE`로 고정한다.
- 시설(식당·화장실·충전소) 후보는 Pleos SDK에 시설 검색 API가 없어, 지금은 앱에 넣은 시연 구간 시설 데이터(실제·가상 혼합)를 쓰고 화면에 출처를 표시한다. 외부 시설 데이터(API)는 공모전 규정을 운영사에 확인한 뒤 붙인다 (ADR-0001).
- 상시 무료 운영, 현금 지출 0원 (ADR-0005). 무료 한도를 넘을 수 있는 외부 API는 가상 데이터로 대체한다.

**개발 일정**:

| 시점 | 내용 |
|---|---|
| ~11-15 (1차 접수) | 최소 동작 앱 + 시연 영상 + GitHub(소스·APK) |
| ~12-03 (2차 PT 전) | 핵심 SDK 연계·예외 대응을 에뮬레이터에서 실제 동작으로 검증 |
| 선정 후 | 준비 중 SDK 오픈 시 전환, 앱 마켓 입점 시 가상 데이터를 실제 데이터로 교체 |

**검증 방식**: 단위 테스트 + 에뮬레이터 E2E(`adb` + Virtual Console로 기어·배터리·충전·속도 조작).

## 6. 기대효과 및 발전 가능성

- **사용자 가치**: 충전과 가족 필요를 한 번에 비교해 정차 계획 시간을 줄이고, 주행 중에도 안전하게 경유지를 반영한다.
- **타깃**: 전기차로 가족 여행하는 운전자·성인 동승자. 내연기관 차량은 후속 범위.
- **예상 MAU / Retention**: 근거 있는 수치가 아직 없어 목표값은 정하지 않았다. 산정 방식은 MAU = Pleos 탑재 전기차 중 가족 동반 장거리 이동 차량 수 × 설치율 × 월간 사용률이며, 탑재 대수와 설치율은 App Market 입점 후 실제 값으로 채운다. 가족 여행은 주말·연휴에 몰리므로 월간보다 분기 재사용률(같은 차량이 다음 장거리 여행에서 다시 쓰는 비율)을 Retention 지표로 본다. 시연 단계에서는 정차 계획 시간·선택 이유·해결되지 않은 필요를 관찰해 측정한다.
- **확대 계획**: 내연기관 주유 전후 안내, 음성 요청(STT 오픈 후), 정차 가치·재사용 지표 수집(동의 기반), 실제 시설 데이터로 전환 후 앱 마켓 입점.
- **한계**: 소규모 표본은 일반화할 수 없고, 선택이 실제 방문을 뜻하지 않는다.
